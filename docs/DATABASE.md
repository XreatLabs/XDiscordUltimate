# Database

XDiscordUltimate stores linked accounts, verification codes, tickets, moderation records, and basic player counters in a database. The backend is selected in `config.yml` under `database.type`.

## Configuration

```yaml
database:
  type: "sqlite"
  sqlite:
    file: "data.db"
  mysql:
    host: "localhost"
    port: 3306
    database: "xdiscord"
    username: "root"
    password: "password"
    ssl: false
```

`type` accepts `sqlite` (default), `mysql`, or `postgresql`. The SQLite file lives inside `plugins/XDiscordUltimate/`. MySQL requires an existing database and valid credentials; `ssl` is appended to the JDBC URL as `useSSL`.

PostgreSQL is supported by the code but has no section in the default config. Set `type: "postgresql"` and add:

```yaml
database:
  postgresql:
    host: "localhost"
    port: 5432
    database: "xdiscord"
    username: "postgres"
    password: "password"
```

Connections are pooled with HikariCP (max pool 10, min idle 2, 30s connection timeout, `SELECT 1` validation). The schema is created on first start and migrations are tracked in the `schema_versions` table (`version_key`, `version_value`, `applied_at`; current schema version: 1). If initialization fails, the plugin disables itself with `Failed to initialize database!`.

## Tables

### verified_users

Linked Discord and Minecraft accounts.

| Column | Type | Notes |
|--------|------|-------|
| minecraft_uuid | VARCHAR(36) | Primary key |
| discord_id | VARCHAR(20) | Not null, unique |
| verified_at | TIMESTAMP | Defaults to current timestamp |
| minecraft_name | VARCHAR(16) | |
| discord_name | VARCHAR(32) | Refreshed when a linked member changes nickname |

### verification_codes

Pending codes generated by the Discord `/verify` command.

| Column | Type | Notes |
|--------|------|-------|
| discord_id | VARCHAR(20) | Primary key |
| code | VARCHAR(10) | Not null, unique |
| username | VARCHAR(16) | Discord username at generation time |
| created_at | BIGINT | Epoch millis |
| expires_at | BIGINT | Epoch millis; expired rows are cleaned periodically |

### tickets

| Column | Type | Notes |
|--------|------|-------|
| id | INTEGER | Primary key, auto increment |
| minecraft_uuid | VARCHAR(36) | Not null, references verified_users |
| discord_channel_id | VARCHAR(20) | Set when the channel is created |
| status | VARCHAR(20) | Default `OPEN`; closed tickets are set to `CLOSED` |
| created_at | TIMESTAMP | Defaults to current timestamp |
| closed_at | TIMESTAMP | Null until closed |
| subject | TEXT | |

### ticket_messages

| Column | Type | Notes |
|--------|------|-------|
| id | INTEGER | Primary key, auto increment |
| ticket_id | INTEGER | Not null, references tickets |
| sender_uuid | VARCHAR(36) | |
| sender_type | VARCHAR(10) | |
| sent_at | TIMESTAMP | Defaults to current timestamp |

### moderation_logs

| Column | Type | Notes |
|--------|------|-------|
| id | INTEGER | Primary key, auto increment |
| action_type | VARCHAR(20) | Not null, for example `REPORT` |
| moderator_uuid | VARCHAR(36) | |
| reason | TEXT | |
| timestamp | TIMESTAMP | Defaults to current timestamp |
| expires_at | TIMESTAMP | Null when not expiring |
| active | BOOLEAN | Default true |

### player_stats

Basic per-player counters.

| Column | Type | Notes |
|--------|------|-------|
| minecraft_uuid | VARCHAR(36) | Primary key |
| joins | INTEGER | Default 0 |
| messages_sent | INTEGER | Default 0 |
| deaths | INTEGER | Default 0 |
| playtime_minutes | INTEGER | Default 0 |
| last_seen | TIMESTAMP | |
| first_join | TIMESTAMP | |

### activity_rewards

| Column | Type | Notes |
|--------|------|-------|
| id | INTEGER | Primary key, auto increment |
| discord_id | VARCHAR(20) | Not null |
| reward_type | VARCHAR(50) | |
| reward_data | TEXT | |
| claimed | BOOLEAN | Default false |
| created_at | TIMESTAMP | Defaults to current timestamp |
| claimed_at | TIMESTAMP | Null until claimed |

## Indexes

Created alongside the tables: `idx_discord_id` (verified_users.discord_id), `idx_verification_code` (verification_codes.code), `idx_verification_expires` (verification_codes.expires_at), `idx_ticket_status` (tickets.status), `idx_mod_moderator` (moderation_logs.moderator_uuid), `idx_mod_active` (moderation_logs.active).

## What is not in the database

Ticket panel persistence lives in `tickets.yml` with timestamped copies in `backups/tickets-<timestamp>.yml`, weekly/monthly stat snapshot baselines live in `stats-snapshots.yml`, and `/xdiscord export [all|verified|stats|tickets]` writes JSON exports to `exports/`.

## Switching backends

Database contents are not migrated automatically; point the plugin at the new backend and move data with your own database tooling if needed.
